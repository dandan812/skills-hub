# v0.9.0 Skill 发现扫描设置

## 背景

Skills Hub 会在启动时扫描已检测工具的全局 Skills 目录，并在“我的 Skills”页面提示可导入内容。此前扫描来源固定，用户无法关闭不希望纳入发现流程的目录；同时，工具目录下的普通子目录也可能被当成可导入 Skill 展示。

v0.9.0 增加独立的扫描来源设置。用户可以按实际目录控制是否参与发现扫描，保存后立即刷新发现结果。该配置只影响“发现并导入”流程，不改变工具启用状态，也不会删除已托管或已同步的 Skill。

## 交互设计

扫描设置提供两个入口，并复用同一个弹窗：

- “我的 Skills”页面存在发现结果时，在“查看并导入”旁显示低强调的“扫描设置”快捷入口。
- 设置页始终显示“发现与扫描”卡片。即使所有来源均已关闭、发现横幅不再显示，用户仍可从这里重新启用来源。

弹窗按扫描来源展示名称、实际路径和开关。保存按钮使用“保存并重新扫描”，明确设置生效后会立即刷新发现结果。

## 配置模型

配置以 `discovery_scan_config_v1` 键保存到现有 `settings` 表：

```json
{
  "disabled_source_keys": [
    "tool_dir:.claude/skills",
    "claude_plugins"
  ]
}
```

- 内置工具目录使用 `tool_dir:<relative-skills-dir>` 作为稳定来源 key。
- 多个工具共享同一物理 Skills 目录时，在界面中合并为一个扫描来源，并共享同一个开关。
- Claude 用户级插件使用独立的 `claude_plugins` 来源 key。
- 未保存过配置时，所有可用来源默认开启，保持升级前行为。
- 当前未显示但已经关闭的来源会继续保留在配置中，避免工具暂时卸载后丢失用户选择。

本功能复用现有键值设置表，不修改数据库 schema，也不需要迁移。

## 扫描规则

- 只列出检测目录存在的内置工具扫描来源。
- 关闭一个目录后，所有使用该目录的内置工具扫描都会跳过该来源。
- Claude 插件扫描可独立关闭，不受 `~/.claude/skills` 开关影响。
- 工具 Skills 根目录下只有包含 `SKILL.md`（文件名大小写不敏感）的一级子目录才会作为 Skill。
- Codex 的 `.system`、Skills Hub 中央仓库及已托管同步目标继续使用原有排除规则。
- 扫描结果只用于提示和导入；用户确认导入前不会自动同步。

## IPC

新增两个 Tauri 命令：

- `get_discovery_scan_settings`：返回当前可用扫描来源、路径、启用状态以及完整禁用 key 列表。
- `set_discovery_scan_config`：保存禁用来源，返回规范化后的设置；前端随后重新加载 onboarding plan。

## 验证

自动化测试覆盖：

- 关闭指定工具目录后跳过该来源，其他来源继续扫描。
- 不包含 `SKILL.md` 的普通目录不会进入发现结果。
- 配置持久化、未知 key 过滤和重复 key 去重。
- 前端开关初始状态构建，以及保存时保留当前不可见的禁用来源。
- 中英文文案、TypeScript 构建、Rust 格式、Clippy 和完整测试套件。
